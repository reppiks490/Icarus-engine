# Non-Databento provider coverage

User directive 2026-10-07: account for every non-Databento API across Icarus and related repositories; collect everything actually accessible rather than selecting six assets. Databento collectors, budgets, credentials and workflows are outside this change. Scheduled ChatGPT loops remain paused and no remote model API is called.

The catalog accounts for 1,105 operations in pinned official specifications and documentation: Massive 148, Intrinio 248, EODHD 88, Twelve 185, FMP 230, Quiver 40, FRED 31, Tiingo 29, Alpaca 17, Bybit 56 parameter variants and Tick Stream 33. These counts are an inventory, not a claim that all endpoints work or every provider catalog is complete. Unknown parameters, unsupported category combinations, non-GET operations and unimplemented transports are reported explicitly. Official examples qualify initial entitlement probes; they are not full historical acquisition.

`provider-exhaustive-collection.yml` runs hourly at minute 11 UTC, with independent provider jobs. All discovered instrument identities, including exchange identity, remain in a persistent SQLite catalog. Dataset templates expand lazily across the catalog; there is no six-symbol asset allowlist. Supported next-page URLs/tokens and offsets resume after rate limits. No next-page signal is not proof of complete history. API availability is separate from successful collection. A 20-request ceiling per provider per job and 13-second request spacing prevent uncontrolled bursts; denied endpoints retry weekly, transient failures and completed jobs refresh daily. These are transport limits, not endpoint or asset selection limits. Coverage can remain behind provider changes and finite quotas; no maximum-potential or zero-lag guarantee is made.

Credentials use GitHub Actions repository secrets. Existing EODHD/FMP/Tiingo/FRED references are reused. Additional accepted names are in each provider's receipt and runtime `PROVIDERS` mapping. Secret values, auth headers, raw provider errors and credential-bearing URLs are never written to reports. Read-only market-data Alpaca requests do not place orders. Bybit public data needs no account key; regional/IP or endpoint access failures stay visible.

Licensed raw data must not be redistributed through these public Git repositories. Payloads are compressed and authenticated-encrypted for seven-day Actions artifacts using an HKDF-derived AES-256 key from the existing provider credential. Optional `ICARUS_DATA_ARCHIVE_KEY` overrides this with a base64-encoded 32-byte AES key. No additional key is needed for authenticated providers; owner-held provider keys decrypt their archives through `tools.provider_archive` into a private research intake directory. Rotation requires retaining the original credential for old archives. Public/keyless providers need the override key to retain encrypted payloads. Archive failures are explicit. Existing collectors continue their existing compact research outputs; The collector emits descriptive numeric research features (sample counts, means, ranges and dispersion) into its evidence receipts; it does not claim training, scientific discovery or strategy promotion. Automatic private archive download into the live engine remains unverified.

State is restored from provider-specific Actions caches. Authenticated providers additionally commit AES-GCM encrypted SQLite checkpoints, so cache eviction does not erase queue progress. Credential rotation requires the prior archive credential or the optional stable archive key. Immutable public receipts and MCP routing events survive successful Git pushes, and artifacts provide push-failure recovery. Full historical time ranges, all resolutions, complete parameter cross-products, WebSocket streams, flat-file archives, FRED v2 bulk/GeoFRED, full Alpaca dataset catalog and private downstream dataset ingestion remain unverified. Denied or missing capabilities must not be presented as harvested data.

Exa and other tool-only research services remain in the provider inventory with explicit adapter/credential/monetary-budget gaps. Exa uses metered search and is not a finite catalog that can be exhausted; no unknown recurring bill is enabled. OpenAI/Anthropic paid inference remains disabled under the token-stop directive. GitHub connector permissions do not expose or export connector-managed data credentials.

Repository audit covers all 18 repositories returned for the owner and all workflow files in the 10 ICARUS-related repositories, with tree truncation checked. `Icarus` and `Icarus-engine` are the main repositories; `main` is a branch, not a separate repository. Intrinio is owned by `Icarus`; other providers prefer `Icarus-engine`. A secondary repository takes over only when the preferred owner has a fresh explicit missing-key or authentication failure; sibling tests and liveness jobs are not called data acquisition. The inventory records existing ownership to prevent replacing unrelated work.

Tests: `python -m pytest tests/test_provider_exhaustive_collection.py -q`. Negative controls cover credential absence, redirect/pagination exfiltration, rate-limit resume, denied-endpoint suppression, incomplete parameter binding, full discovered-universe expansion and strict Databento exclusion. Read actual canary receipts before claiming connection or useful recurring ingestion.
